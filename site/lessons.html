3.1. Методические рекомендации

От исходного приложения к проверенному обновлению

  1. 01

    Один рабочий проект

    Выбрать ранее принятый проект своей области и сохранить его копию в Source. Если проекта нет, распаковать предоставленную основу в Source и адаптировать подписи и встроенные данные. Создать Work как рабочую копию. Демонстрационный ServiceDesk служит чтению и сверке, его отдельная разработка перед своей областью не требуется.

  2. 02

    Задача сопровождения

    Оператор сервисного журнала умеет просматривать встроенные заявки, но хочет обмениваться CSV. Сначала докажите исправность окна, затем воспроизведите ошибки обмена. Исправлять их по отдельности: так повторная проверка показывает причину улучшения. После общей диагностики добавить выборку для оператора и выполните собственное предметное правило.

  3. 03

    Что считать рабочей копией

    Распаковать исходный проект по ссылке под заголовком в папку Source. Для экспериментов создать её копию Work. Не менять Source. CSV-заготовка нужна для сравнения и воспроизведения; исправленный пример открывать для сверки после собственного исправления. Это три версии одного приложения с одинаковыми именами классов, поэтому их исходники нельзя складывать в один проект.

  4. 04

    Среда

    В проверенной среде используются Windows, Visual Studio и .NET SDK 10.0.401. В файле ServiceDesk.csproj указан net10.0-windows и UseWPF=true. SDK компилирует проект; Desktop Runtime выполняет WPF-приложение. Если Visual Studio не поддерживает этот SDK или не видит WPF-компоненты, остановить сборку и сообщите преподавателю фактическую ошибку. Не менять целевую платформу наугад.

3.3. Методические рекомендации

Контрольная дата как входное значение

  1. 01

    Назначение

    Контрольная дата — день, относительно которого проверяются сроки. DateTime.Today зависит от дня запуска и не позволяет воспроизвести сохранённый контрольный ответ. CheckDate читает выбранную дату из DatePicker; одинаковый день передаётся счётчику и OperatorView.Select.

  2. 02

    Где изменить

    В уже предоставленных Source и Draft поле ControlDate находится в MainWindow.xaml, значение назначается в конструкторе MainWindow, а свойство CheckDate — в MainWindow.xaml.cs. При переносе в ранее принятый проект добавить поле, событие ControlDate_Changed и свойство из полных файлов основы; заменить передачу DateTime.Today в обработчиках на CheckDate. Не менять параметр today внутри чистых методов.

  3. 03

    Проверка

    В окне установить 01.10.2026. Открыть demo-operator.csv и получить три демонстрационные записи 105, 101, 103. Установить 04.11.2026 и повторить отбор: получится пять открытых просроченных записей. Вернуть 01.10.2026. Проверка меняет только значение в приложении.

    Проверка. Системные часы прежние; результат меняется после повторного действия с новой выбранной датой.

D1: результат чтения содержит данные и предупреждения

  1. 01

    Согласованная замена

    Остановить отладку Shift+F5. В Work/MainWindow.xaml.cs после существующей строки internal record Ticket добавить следующую одну строку. Внутри CsvStore заменить целиком метод public static List<Ticket> Read(string path), включая его фигурные скобки, следующим методом Read. Остальные методы пока оставить прежними.

  2. 02

    Код для указанного изменения

    internal record ReadResult(List<Ticket> Tickets, List<string> Warnings);
  3. 03

    Код для указанного изменения

        private const string Header = "Id;Item;Owner;Due;Status";

    public static ReadResult Read(string path)
    {
        var tickets = new List<Ticket>();
        var warnings = new List<string>();
        var lines = File.ReadAllLines(path, Encoding.UTF8);
        if (lines.Length == 0 || lines[0].TrimStart('\uFEFF') != Header)
            throw new InvalidDataException($"Ожидается заголовок {Header}");
        for (int index = 1; index < lines.Length; index++)
        {
            if (string.IsNullOrWhiteSpace(lines[index])) continue;
            var cells = lines[index].Split(';');
            string? reason = null;
            if (cells.Length != 5) reason = "ожидается пять полей";
            else if (!int.TryParse(cells[0], out _)) reason = "неверный Id";
            else if (string.IsNullOrWhiteSpace(cells[1]) || string.IsNullOrWhiteSpace(cells[2])) reason = "пустое обязательное поле";
            else if (!DateTime.TryParseExact(cells[3], "dd.MM.yyyy", CultureInfo.InvariantCulture, DateTimeStyles.None, out _)) reason = "неверная дата";
            else if (cells[4] != "Открыта" && cells[4] != "Завершена") reason = "неверный статус";
            if (reason != null) { warnings.Add($"Строка {index + 1}: {reason}"); continue; }
            tickets.Add(new Ticket(int.Parse(cells[0], CultureInfo.InvariantCulture), cells[1], cells[2],
                DateTime.ParseExact(cells[3], "dd.MM.yyyy", CultureInfo.InvariantCulture), cells[4]));
        }
        return new ReadResult(tickets, warnings);
    }
  4. 04

    Смысл чтения

    ReadAllLines получает строки в UTF-8. Заголовок проверяется до цикла. Пустые строки не являются заявками; пять полей проверяются до индексов. TryParse возвращает успех вместо исключения; TryParseExact требует однозначную дату. reason содержит первую найденную причину. continue пропускает только текущую строку. index+1 — её физический номер с учётом заголовка. Хорошая строка создаёт Ticket и остаётся доступной.

  5. 05

    Завершить зависимое изменение

    Внутри MainWindow заменить целиком private void LoadCsv(string path) следующим фрагментом. В App.xaml.cs заменить весь файл кодом из следующего блока. Это адаптирует запуск и режим самопроверки к ReadResult. Пока эти три связанные замены не закончены, промежуточная сборка может сообщать несовместимые типы; это не контрольная точка.

D2: запись соблюдает тот же контракт, что чтение

  1. 01

    Точное место правки

    В Work/MainWindow.xaml.cs, внутри CsvStore, заменить целиком public static void Write(string path, IEnumerable<Ticket> rows) следующим методом. Константа Header уже появилась вместе с Read: если её ещё нет, добавить private const string Header = "Id;Item;Owner;Due;Status"; непосредственно после открывающей скобки CsvStore. Не объявлять Header дважды.

  2. 02

    Код для указанного изменения

        public static void Write(string path, IEnumerable<Ticket> tickets)
    {
        var lines = new List<string> { Header };
        foreach (var t in tickets)
        {
            if (new[] { t.Item, t.Owner, t.Status }.Any(value => value.Contains(';') || value.Contains('\n') || value.Contains('\r')))
                throw new InvalidDataException("В поле нельзя использовать разделитель или перевод строки");
            lines.Add($"{t.Id};{t.Item};{t.Owner};{t.Due.ToString("dd.MM.yyyy", CultureInfo.InvariantCulture)};{t.Status}");
        }
        File.WriteAllLines(path, lines, Encoding.UTF8);
    }
  3. 03

    Зачем две проверки

    Сначала формируется весь список строк, затем File.WriteAllLines записывает его в UTF-8. ToString с InvariantCulture сохраняет dd.MM.yyyy независимо от системной культуры. В этом простом контракте нет CSV-кавычек и экранирования: точка с запятой и перевод строки внутри поля отклоняются, чтобы не создать повреждённый файл. Отказ происходит до записи содержимого.

  4. 04

    Сравнить значения

    Собрать, открыть demo-valid.csv, экспортировать в roundtrip.csv и открыть этот результат. В текстовом редакторе сравнить заголовок, оба Id, Item, Owner, Due и Status; одинакового количества недостаточно. Вернитесь к demo.csv: предупреждение о строке 4 должно остаться. Экспорт сохраняет загруженные корректные записи и не восстанавливает отвергнутую строку.

3.8. Методические рекомендации

D3: просрочка зависит от срока и состояния

  1. 01

    Заменить одно правило

    Внутри CsvStore заменить целиком метод CountOverdue следующим фрагментом. Не менять TestData.CountOverdue: он был правильным и нужен для сравнения. Два правила должны давать одинаковый результат на одинаковых данных.

  2. 02

    Код для указанного изменения

        public static int CountOverdue(IEnumerable<Ticket> tickets, DateTime today) =>
        tickets.Count(t => t.Status != "Завершена" && t.Due.Date < today.Date);
  3. 03

    Разобрать выражение

    Count считает только элементы с истинным условием. Статус завершения исключается до сравнения дат. Due.Date и today.Date сравнивают календарные дни без времени. Срок на контрольную дату ещё не просрочен. Параметр today позволяет проверить правило на заданную дату без изменения часов Windows.

  4. 04

    Граничная проверка

    Собрать и открыть demo-valid.csv: после «Просрочено» ожидается 1. В копии CSV создать открытую вчера, завершённую вчера и открытую сегодня — ожидается 1; заменить вчера на завтра — ожидается 0. Затем снова загрузите demo.csv и нажать «Тестовые данные»: два разных источника данных должны оставаться рабочими.

3.9. Методические рекомендации

Отбор для оператора без потери исходного списка

  1. 01

    Демонстрационная задача

    В отдельной демонстрационной области оператору нужны незавершённые просроченные заявки по сроку, затем по Id. Полный импорт должен оставаться в памяти и экспортироваться независимо от того, какую выборку сейчас видит оператор. Так пользовательский просмотр не превращается в потерю данных.

  3. 03

    Код для указанного изменения

    internal static class OperatorView
{
    public static List<Ticket> Select(IEnumerable<Ticket> rows, DateTime today) =>
        rows.Where(t => t.Status == "Открыта" && t.Due.Date < today.Date)
            .OrderBy(t => t.Due).ThenBy(t => t.Id).ToList();
}

3.10. Методические рекомендации

Как перенести правило на индивидуальную область

  1. 01

    Собрать условие до кода

    Из карточки выписать статус, ответственного, границы даты, порядок и ограничение числа записей. Взять фактические имена ответственных из своего контрольного CSV. Перевести каждую часть в отдельное условие; не копировать контрольные Id демонстрации в код.

  2. 02

    Сравнения и календарные границы

    t.Due.Date < today.Date — срок раньше выбранного дня; <= включает сам день. Диапазон задаётся двумя сравнениями через &&. today.Date.AddDays(-N) означает день за N суток до контрольного. «Не менее N дней назад» включает границу, «строго менее N дней назад» требует открытой нижней границы. Для статуса и Owner использовать сравнение строк с точными значениями из CSV.

  3. 03

    Порядок и ограничение

    Where отбирает записи. OrderBy задаёт первый ключ, ThenBy — следующий; OrderByDescending и ThenByDescending меняют направление соответствующего ключа. После сортировки Take(N) оставляет первые N. ToList создаёт отдельное представление. Исходный tickets не заменять результатом.

  4. 04

    Самостоятельная проверка

    Вручную отметить подходящие строки своего контрольного CSV и упорядочить их по условию. Сравнить с порядком Id в карточке на 01.10.2026. Добавить равный срок, день на границе и запись с противоположным статусом; заранее определить ожидаемое включение. Этот разбор не предоставляет готовый метод для назначенной области.

3.11. Методические рекомендации

Регрессионная матрица и диагностика ошибок

  1. 01

    Набор проверок

    На копиях входа проверить: верный файл; неполную строку после хорошей; неверные Id, дату и статус; пустые Item/Owner; файл только с заголовком; неверный заголовок; отсутствующий файл; строку с лишним разделителем.   4. 04

    HeaderExchange.cs — полный демонстрационный адаптер

    using System.IO;
using System.Text;

namespace ServiceDeskWpf;

// Optional extension: adapt the order, then reuse the accepted strict reader.
internal static class HeaderExchange
{
    private static readonly string[] Columns = ["Id", "Item", "Owner", "Due", "Status"];

    public static ReadResult Read(string path)
    {
        var lines = File.ReadAllLines(path, Encoding.UTF8);
        if (lines.Length == 0) throw new InvalidDataException("Отсутствует заголовок CSV");
        var header = lines[0].TrimStart('\uFEFF').Split(';');
        if (header.Length != Columns.Length || header.Distinct(StringComparer.Ordinal).Count() != Columns.Length ||
            Columns.Any(name => !header.Contains(name, StringComparer.Ordinal)))
            throw new InvalidDataException("Заголовок должен содержать Id, Item, Owner, Due, Status по одному разу");
        var order = Columns.Select(name => Array.IndexOf(header, name)).ToArray();
        var normalized = new List<string> { string.Join(';', Columns) };
        foreach (var line in lines.Skip(1))
        {
            if (string.IsNullOrWhiteSpace(line)) { normalized.Add(line); continue; }
            var cells = line.Split(';');
            // Preserve malformed rows and physical line numbers for the existing validator.
            normalized.Add(cells.Length == Columns.Length ? string.Join(';', order.Select(i => cells[i])) : line);
        }
        var temp = Path.GetTempFileName();
        try { File.WriteAllLines(temp, normalized, Encoding.UTF8); return CsvStore.Read(temp); }
        finally { File.Delete(temp); }
    }
}
