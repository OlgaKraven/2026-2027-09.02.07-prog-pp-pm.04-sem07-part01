Исходная система

Демонстрационная предметная область — сервисный журнал учебного центра. Объекты «Проектор» и «Ноутбук» используются только для объяснения приёмов. Стартовый ServiceDesk-source.zip не имеет CSV и позволяет отдельно проверить таблицу и счётчик. После этого используется CSV-заготовка с намеренными дефектами, затем исправленный пример для сверки.

Связь этапов

Каждый следующий этап опирается на проверенный предыдущий: работа окна → контракт данных → воспроизведение D1–D3 → правка по причине → регрессия → обновление. Если пропустить исходную проверку, сообщение импорта нельзя уверенно отличить от ошибки формы. Если не зафиксировать вход и ожидание, невозможно доказать, что изменение устранило исходный дефект.

Где лежат файлы

Прямые ссылки под этой страницей скачивают архив исходного проекта, заготовку интеграции, демонстрационный CSV и исправленный пример. Распакуйте каждый архив в отдельную папку. Данные demo.csv и demo-valid.csv положите в отдельный каталог данных, чтобы не путать их с исходниками. Все пути в инструкции относятся к содержимому скачанных архивов, а не к служебной папке преподавателя.

Что вы открыли

ServiceDesk.csproj задаёт Windows Forms и целевую платформу. Program.cs содержит модель Ticket, генератор TestData и форму MainForm. Ticket хранит пять значений; TestData создаёт две записи и считает просроченные. MainForm создаёт DataGridView, строку состояния и кнопки. Этот небольшой исходник удобно проверить до добавления файлового обмена.

Первый контроль

Program-starter.cs: строки 1–18

using System.Windows.Forms;

namespace ServiceDesk;

internal record Ticket(int Id, string Item, string Owner, DateTime Due, string Status);

internal static class TestData
{
    public static List<Ticket> Create(DateTime today) =>
    [
        new Ticket(101, "Проектор", "Ирина", today.AddDays(-2), "Открыта"),
        new Ticket(102, "Ноутбук", "Павел", today.AddDays(-1), "Завершена")
    ];

    public static int CountOverdue(IEnumerable<Ticket> tickets, DateTime today) =>
        tickets.Count(t => t.Status != "Завершена" && t.Due.Date < today.Date);

Почему это работает и как проверить

TestData.Create(DateTime.Today) создаёт одну открытую запись с прошедшей датой и одну завершённую. CountOverdue исключает завершённые записи и сравнивает только календарную дату. Повторите проверку кнопки после изменения демонстрационных значений своего варианта.

    private void LoadTestData()
    {

Пять полей и их смысл

Id — номер заявки; Item — объект, например «Проектор»; Owner — ответственный; Due — контрольная дата; Status — «Открыта» или «Завершена». Первая строка Id;Item;Owner;Due;Status обязательна. Сохраните точку с запятой как разделитель. Обычная запятая и локальный формат даты здесь не являются частью договора.

Проверка файла глазами

В demo.csv строки 2 и 3 имеют по пять полей, а строка 4 заканчивается после Owner. Перед запуском напишите ожидаемое: две корректные записи должны пережить ошибку соседней строки, предупреждение должно назвать строку 4. Сравните с текущей заготовкой: исключение появляется раньше обновления таблицы.

Где искать первопричину

В заготовке откройте Program.cs и найдите CsvStore.Read. Посмотрите, как создаётся массив cells и где читается cells[4]. Доступ к несуществующей ячейке объясняет ошибку. Следующий раздел показывает безопасный порядок: заголовок файла проверяется один раз, каждая запись валидируется до преобразования.

Разбор исходного кода

Устойчивое чтение файла

Где выполнять действие

В рабочем Program.cs создайте CsvStore после записей Ticket и ReadResult. Внутри него добавьте Header и начало метода Read. Заголовок проверяется до цикла; неверный заголовок делает весь файл непригодным.

Program-fixed.cs: строки 10–20

internal static class CsvStore
{
    private const string Header = "Id;Item;Owner;Due;Status";

    public static ReadResult Read(string path)
    {
        var tickets = new List<Ticket>();
        var warnings = new List<string>();
        var lines = File.ReadAllLines(path, Encoding.UTF8);
        if (lines.Length == 0 || lines[0].TrimStart('\uFEFF') != Header)
            throw new InvalidDataException($"Ожидается заголовок {Header}");

Почему это работает и как проверить

Здесь создаются два списка: принятые записи и предупреждения. Фрагмент обрывается перед циклом, поэтому завершите метод на следующей странице и только затем собирайте проект. После завершения на файле только с заголовком метод вернёт два пустых списка, а при неверном заголовке выдаст общую ошибку.

Разбор исходного кода

Валидация одной строки без потери остальных

Где выполнять действие

Продолжите метод Read после проверки заголовка. В цикле сначала Split, затем проверка Length и только после неё обращения к полям. Для Id и даты используйте TryParse, для пустых полей и статуса — явные условия.

Program-fixed.cs: строки 21–37

        for (int index = 1; index < lines.Length; index++)
        {
            if (string.IsNullOrWhiteSpace(lines[index])) continue;
            var cells = lines[index].Split(';');
            string? reason = null;
            if (cells.Length != 5) reason = "ожидается пять полей";
            else if (!int.TryParse(cells[0], out _)) reason = "неверный Id";
            else if (string.IsNullOrWhiteSpace(cells[1]) || string.IsNullOrWhiteSpace(cells[2])) reason = "пустое обязательное поле";
            else if (!DateTime.TryParseExact(cells[3], "dd.MM.yyyy", CultureInfo.InvariantCulture, DateTimeStyles.None, out _)) reason = "неверная дата";
            else if (cells[4] != "Открыта" && cells[4] != "Завершена") reason = "неверный статус";
            if (reason != null) { warnings.Add($"Строка {index + 1}: {reason}"); continue; }
            tickets.Add(new Ticket(int.Parse(cells[0], CultureInfo.InvariantCulture), cells[1], cells[2],
                DateTime.ParseExact(cells[3], "dd.MM.yyyy", CultureInfo.InvariantCulture), cells[4]));
        }
        return new ReadResult(tickets, warnings);
    }

Почему это работает и как проверить

Предупреждение содержит index + 1, потому что индекс массива начинается с нуля, а строка файла — с единицы. continue пропускает только текущую запись. На demo.csv ожидаются 101 и 102 плюс предупреждение о строке 4. Для неверной даты создайте копию файла и проверьте, что оставшаяся запись видна.

Разбор исходного кода

Экспорт в совместимом формате

Где выполнять действие

В том же CsvStore после Read добавьте Write. Откройте demo-valid.csv и сравните точный заголовок. Метод должен сначала записать Header, затем сформировать пять полей каждой заявки. До записи проверьте текстовые поля на разделитель и перевод строки.

Program-fixed.cs: строки 38–49

    public static void Write(string path, IEnumerable<Ticket> tickets)
    {
        var lines = new List<string> { Header };
        foreach (var t in tickets)
        {
            if (new[] { t.Item, t.Owner, t.Status }.Any(value => value.Contains(';') || value.Contains('\n') || value.Contains('\r')))
                throw new InvalidDataException("В поле нельзя использовать разделитель или перевод строки");
            lines.Add($"{t.Id};{t.Item};{t.Owner};{t.Due.ToString("dd.MM.yyyy", CultureInfo.InvariantCulture)};{t.Status}");
        }
        File.WriteAllLines(path, lines, Encoding.UTF8);
    }

Почему это работает и как проверить

Формат dd.MM.yyyy с InvariantCulture не зависит от настроек компьютера. После сборки экспортируйте два корректных значения и снова импортируйте результат; сравните все пять полей. Если название объекта содержит точку с запятой, получите понятную ошибку вместо молчаливо повреждённого CSV.

Показ записей и предупреждений

Где выполнять действие

После OpenCsv добавьте LoadCsv. Он вызывает CsvStore.Read: сначала сохраняет Tickets в поле формы и обновляет DataGridView, затем показывает Warnings. Общую ошибку отсутствующего файла ловит как исключение импорта.

Program-fixed.cs: строки 86–98

    private void LoadCsv(string path)
    {
        try
        {
            var result = CsvStore.Read(path);
            tickets = result.Tickets;
            grid.DataSource = tickets.ToList();
            status.Text = $"Загружено: {tickets.Count}; пропущено: {result.Warnings.Count}";
            if (result.Warnings.Count > 0) MessageBox.Show(string.Join(Environment.NewLine, result.Warnings), "Предупреждения импорта");
        }
        catch (Exception ex) { MessageBox.Show(ex.Message, "Ошибка импорта"); }
    }

Почему это работает и как проверить

При demo.csv форма показывает две записи, статус — «Загружено: 2; пропущено: 1», предупреждение — строку 4. После закрытия окна таблица остаётся заполненной.

Самопроверка обмена

Где выполнять действие

В конце MainForm добавьте точку входа Main. Режим --self-test принимает путь к CSV, выполняет импорт, экспорт во временный файл и повторное чтение. Этот код остаётся в проверенном демонстрационном примере.

Program-fixed.cs: строки 107–122

    [STAThread]
    private static void Main(string[] args)
    {
        if (args.Length == 2 && args[0] == "--self-test")
        {
            var result = CsvStore.Read(args[1]);
            var target = Path.GetTempFileName();
            try
            {
                CsvStore.Write(target, result.Tickets);
                var roundtrip = CsvStore.Read(target);
                if (roundtrip.Warnings.Count != 0 || !result.Tickets.SequenceEqual(roundtrip.Tickets))
                    throw new InvalidOperationException("Повторный импорт не совпал");
                Console.WriteLine($"tickets={result.Tickets.Count}; warnings={result.Warnings.Count}; overdue={CsvStore.CountOverdue(result.Tickets, DateTime.Today)}");
                foreach (var warning in result.Warnings) Console.WriteLine(warning);
            }

Почему это работает и как проверить

Выполните dotnet run --project ServiceDesk-fixed.csproj -- --self-test demo.csv: ожидаются tickets=2 и warnings=1. Если обратное чтение отличается, программа выдаёт ошибку вместо сообщения об успехе.

Регрессия и граничные наборы

Матрица до запуска

Для каждого случая запишите вход, ожидаемое число записей, предупреждение и состояние счётчика. Используйте копии CSV: неполная строка, неверный Id, неверная дата, пустой файл с заголовком, завершённая заявка с прошлой датой, открытая с датой сегодня. Сравнение до и после
