# ПП ПМ.04: назначение и приёмка

В согласованной траектории подготовки CSV является обеспечивающим умением ПМ.04:
диагностика существующего приложения, изменение обмена, сохранность данных,
регрессионная проверка и передача обновления. Эта работа не объявляется отдельным
обязательным заданием базового демонстрационного экзамена. Карта соответствия
отдельным заданиям экзамена ведётся в материалах преподавателя, вне учебных страниц.

## Два маршрута

| Группа в карточке | Период | Объём | Результат |
| --- | --- | --- | --- |
| ДКИП-4ХХпрог | 22.12.2026–11.01.2027 | 108 часов | Основной контракт CSV, D1–D3, своё правило отбора, регрессия и откат |
| VДКИП-31Хпрог, ДКИП-3ХХпрог | 10.11.2026–21.12.2026 | 216 часов | Основной результат и новый режим обмена по именам столбцов, диагностика несовместимости и совместимость со старым форматом |

Сохраняются согласованные обобщённые обозначения групп. Для ранее принятого
результата назначается проверка интеграции; повторная реализация основы и D1–D3
не требуется. При отсутствии результата выдаётся входной проект. Между учебной
и производственной практикой одного ПМ сохраняется назначенная область; данные
демонстрации не заменяют собственный вариант.

## Критерии приёмки

1. Контрольная дата 01.10.2026 задана в DatePicker, системные часы не изменены.
2. Основной CSV варианта: две записи приняты, неполная физическая строка 4 названа
   в предупреждении. Дополнительно проверена неверная строка между корректными.
3. Экспорт и повторный импорт сохраняют Id, Item, Owner, Due, Status каждой записи.
4. Выборка для оператора не меняет полный список; экспорт после просмотра содержит
   все шесть контрольных записей. Собственное правило проверяется по карточке.
5. Неверный заголовок и ошибка чтения сохраняют прежнее состояние. Разделитель
   в поле вызывает отказ экспорта до перезаписи целевого файла.
6. Сохранены прежняя программа и исходный CSV. Восстановленный CSV совпадает
   с резервной копией, прежняя программа запускается на восстановленных данных.
7. Длинный маршрут читает канонический и переставленный заголовки, отклоняет
   неизвестные, отсутствующие и повторные имена; экспорт остаётся каноническим.

## Комплект документов

В учебном задании перечислены проект, отчёт со ссылкой на репозиторий, инструкция,
данные и доказательства. Индивидуальное задание, аттестационный лист, справка,
презентация и договор оформляются по выданным формам. Пустой Markdown-шаблон
помогает подготовить содержательную часть отчёта; организационные формы он не заменяет.

Для импорта в EatDoners `assignment.pdf` содержит методические рекомендации,
`guide.pdf` — предметные области. Это соответствует назначению файлов в импортере.
Обновление GitHub не заполняет автоматически пустые поля карточек приложения.

## Сборка и проверка

Из корня репозитория:

```text
py -3 -B tools/build.py
dotnet build stands/ServiceDesk/ServiceDesk.csproj -c Release
dotnet build stands/ServiceDesk-csv-draft/ServiceDesk.csproj -c Release
dotnet run --project tests/ServiceDesk.Checks/ServiceDesk.Checks.csproj -c Release -- .
py -3 -B tools/check_materials.py
```

Для сборки материалов нужны Python 3, ReportLab и Pillow. Для проверок PDF нужен
PyMuPDF. На Windows PDF использует Times New Roman и Consolas; новый визуальный
профиль сохраняет тёмные шапки, красный акцент и серые блоки. Шрифт Golos Text
для сайта хранится с лицензией в `site/assets/fonts/`. На другом устройстве
расположение Times New Roman можно передать через `PP04_TNR_DIR`.

GitHub Actions публикует подготовленный каталог `site/`. Изменение исходного
`content/course.json` или стендов требует повторной локальной сборки материалов.
Полные исходники демонстрации сохраняются в стендах, архивах и справочнике.
